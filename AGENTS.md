# Working on agent-kit

This repo is a portable kit that configures AI coding agents (Claude Code, Gemini CLI) on any machine.
It is not a project scaffold; scaffolding lives in `fastapi-nextjs-starter`.
The general agent rules in `global/AGENTS.md` apply here too; this file only adds what is specific to this repo.

## Check before you finish

Run `scripts/verify.sh fast` after every change and `scripts/verify.sh full` before every commit.
Both must exit 0.

## Tiers

- `global/`: loaded by every tool in every project.
  It must stay stack-free (no framework or library names) and `global/AGENTS.md` stays at most 150 lines.
- `stacks/<name>/`: rules and checks for one stack, attached to a project directory by `kit sync`.
- Project tier: lives in each project, never in this repo.

Every rule exists in exactly one place.
Before adding a rule, grep `global/` and `stacks/` for it and edit the existing one instead.

## Adding things

- A tool: add one file `adapters/<tool>.sh` defining `<tool>_detect`, `<tool>_install_global`, `<tool>_uninstall_global`, `<tool>_sync_project` and `<tool>_doctor`.
  Nothing else may need to change.
- A stack: add one folder `stacks/<name>/` with `rules.md` (max 80 lines), `lint/`, `verify.sh` (`fast` and `full` modes) and `registry.sh`.
  Nothing else may need to change.
- An own skill: add `skills/<name>/SKILL.md`; the folder name must equal the `name:` in its frontmatter.
- A third-party skill: add it under `vendor/skills/<name>/` and record it in `vendor/skills-lock.json`.
  Do not edit vendored skill content.

## Shell constraints

- Dependencies: bash, git, jq only; shellcheck is optional.
- Bash 3.2 compatible: no `declare -A`, `mapfile`, `readarray` or `${var,,}`.
- No GNU-only flags; `sed -i` always takes a suffix argument so it works on BSD and GNU.
- Shared helpers go in `bin/lib.sh`; adapters and scripts source it instead of duplicating logic.
- Files the kit generates in other places carry a header: generated by agent-kit, version, do not edit.

## Safety

- Test installs only with a temporary `HOME`; never against your real `~/.claude` or `~/.gemini`.
- No absolute user paths anywhere in the repo.

## Workflow

Specs live in `docs/specs/`, plans in `docs/plans/`.
Use `git mv` for moves so file history is kept.
Bump `VERSION` (semver) when the installed or synced output changes.
